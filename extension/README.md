# Расширение CRMka — панель клиента в мессенджерах

Браузерное расширение (MV3), которое показывает карточку клиента CRMka рядом с
чатом в веб-мессенджере и пишет переписку в единую историю коммуникаций.

Спецификация и решения: [`docs/messenger-extension.md`](../docs/messenger-extension.md).

## Как запустить (без сборки)

Сборщика нет намеренно: расширение — обычные ES-модули, браузер грузит их как
есть. Не нужен `npm install`, не нужен билд, ничего не надо синхронизировать
между машинами — склонировал репозиторий и загрузил папку.

1. `chrome://extensions` → включить «Режим разработчика»;
2. «Загрузить распакованное расширение» → выбрать папку `extension/`;
3. в CRM открыть **Настройки → Расширение для мессенджеров** (страница скрыта,
   прямая ссылка `/settings/extension`), выпустить токен и скопировать его;
4. открыть `https://web.telegram.org`, нажать иконку расширения — откроется
   боковая панель, вставить адрес CRM и токен;
5. открыть чат с родителем — панель покажет карточку.

Работает в Chrome, Яндекс Браузере и Edge (все на Chromium). Safari не
поддерживается — см. раздел 7 спецификации.

## Проверка типов

Кода на TypeScript нет, но типы описаны в JSDoc и проверяются:

```bash
cd extension
npx tsc -p jsconfig.json
```

Для проверки нужны типы Chrome API: `npx --yes -p @types/chrome tsc -p jsconfig.json`
(глобально ставить ничего не требуется).

## Проверка вёрстки панели

Панель узкая и живёт в тёмной теме мессенджера — ошибки в ней видно только
глазами. Скриншоты снимаются без установки расширения:

```bash
node extension/tools/panel-preview.mjs [папка-для-скриншотов]
```

Скрипт поднимает статику расширения на localhost (ES-модули по `file://`
Chromium не грузит), заглушает `chrome.*` и снимает три состояния: карточка,
форма задачи, форма комментария. Заодно печатает размеры кнопок и то,
подставился ли срок — так уже нашлись форма, висевшая раскрытой (`display: flex`
перебивал атрибут `hidden`), чёрная иконка календаря на чёрном фоне и кнопка
«Сохранить» во всю ширину.

Проверяется только разметка: логика — по `TESTING.md`, с настоящим расширением.
Браузер берётся системный (`CHROMIUM_PATH` переопределяет путь), playwright —
из зависимостей приложения.

## Устройство

```
manifest.json              MV3: sidePanel, storage, tabs + host_permissions
src/background/            service worker — единственный, кто ходит в API
src/panel/                 боковая панель (UI карточки и подключение)
src/content/telegram.js    адаптер Telegram Web (WebK /k и WebA /a)
src/common/                клиент API и общие типы (JSDoc)
```

Разделение ответственности:

- **content script** знает только, какой чат открыт, и умеет отдать видимые
  сообщения. Токена он не видит — иначе его могли бы прочитать скрипты страницы;
- **service worker** хранит настройки, помнит чат по вкладкам и ходит в
  `/api/ext/*` (у него `host_permissions`, поэтому CORS не мешает);
- **панель** только рисует и шлёт команды в service worker.

## Добавление нового мессенджера

1. написать `src/content/<канал>.js` с двумя функциями: определить открытый чат
   (слать `chat-changed` в service worker) и отдать видимые сообщения по запросу
   `collect-messages`;
2. добавить его в `content_scripts` и хост в `host_permissions` манифеста;
3. добавить домен в allow-list CORS на бэкенде (`app/src/lib/ext-cors.ts`).

Панель и API менять не нужно — они одинаковы для всех каналов.

## Границы, которые нельзя переходить

- **Ничего не отправляем автоматически.** Шаблоны и справки вставляются в поле
  ввода, отправляет человек. Массовые рассылки и автоответы — причина банов
  аккаунтов и снятия расширений с публикации;
- **не читаем localStorage/IndexedDB мессенджера** — там токен сессии, именно
  его воруют зловредные расширения;
- **записываем только видимое на экране**, историю не выкачиваем;
- **запись переписки выключена по умолчанию** — включает человек, у центра
  должно быть согласие родителей на обработку.
