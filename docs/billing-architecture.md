# Биллинг — архитектура и решения

Решения приняты: 08.04.2026

## 1. Юридическая структура

**Юрлицо:** ИП Шиманский Д.В.
**Система налогообложения:** АУСН 8% (доходы)
**Регион:** Московская область (АУСН доступна)

### Лимиты АУСН
- Выручка: до 60 000 000 ₽/год
- Сотрудники: до 5 (трудовые договоры; ИП/самозанятые не считаются)
- НДС: не начисляется
- Отчётность: автоматическая (банк → ФНС)

### Когда менять
| Клиентов | Выручка/год | Действие |
|----------|-------------|----------|
| до 500 | до 30 млн | ИП АУСН 8% — текущая схема |
| 500-700 | 30-60 млн | Мониторим приближение к лимиту |
| 700+ | 60+ млн | Открыть ООО, выбрать УСН 6% или АУСН (если лимиты поднимут) |

## 2. Ценообразование

**Базовая цена:** 5 000 ₽/мес за филиал (без НДС)

### Периоды оплаты
| Период | Множитель | Скидка |
|--------|-----------|--------|
| 1 месяц | ×1 | — |
| 3 месяца | ×3 | Нет (пока) |
| 6 месяцев | ×6 | Нет (пока) |
| 12 месяцев | ×12 | Нет (пока) |

> Скидки за длительный период НЕ вводим на старте. Добавим позже, когда проверим unit-экономику и поймём LTV/churn.

### Формула расчёта
```
Сумма = Цена × Кол-во филиалов × Кол-во месяцев
```
Пример: 2 филиала × 5 000 ₽ × 6 мес = 60 000 ₽

### Изменение количества филиалов

**Добавление филиала в середине периода:**
- Доплата = Цена × Оставшиеся полные месяцы
- Выставляется доп. счёт автоматом
- Пример: оплатил 3 мес (апр-июн) за 1 филиал. В мае добавил 2-й → доплата 5 000 × 2 мес = 10 000 ₽

**Удаление филиала:**
- Пересчёт со следующего периода
- Возврат за текущий период НЕ производится (прописано в оферте)

## 3. Документооборот

### Оферта (заменяет индивидуальный договор)
- Публикуется на сайте: umnayacrm.ru/offer
- Акцепт = оплата счёта
- Содержит: предмет, стоимость, порядок оплаты, SLA, порядок приёмки, персональные данные

### Ключевой пункт оферты — приёмка без актов
> «Услуги считаются оказанными надлежащим образом и принятыми Заказчиком, если в течение 5 (пяти) рабочих дней после окончания оплаченного периода Заказчик не направил мотивированную претензию.»

Это стандартная практика для SaaS (Битрикс24, amoCRM, Мегаплан).

### Документы

**Обязательно (автоматом):**
- Счёт на оплату (PDF) — генерируется из CRM
- Оферта на сайте — 1 раз

**По запросу клиента (скачать в ЛК):**
- Акт оказанных услуг (PDF)
- Акт сверки (PDF)

**Не требуется (АУСН, нет НДС):**
- Счёт-фактура
- УПД

## 4. Способ оплаты — безналичный расчёт

### Почему НЕ ЮKassa для B2B
- Комиссия ~3.5% = 350 ₽ с каждых 10 000 ₽
- При 500 клиентах × 10к × 12 мес = **2.1 млн ₽/год** потерь
- Для B2B (ИП → ИП) стандарт — безнал (р/с → р/с), комиссия 0%
- 54-ФЗ чеки для B2B не обязательны

### Основной банк: Т-Банк
**Почему:**
- Счёт уже открыт
- API бесплатный для клиентов
- Лучшая документация среди банков РФ
- Поддержка выставления счетов, webhook при оплате, выписки

### Резервные банки (счета открыты)
- **Точка** — Public API + Pro API, хорошая документация
- **Альфа** — Alfa API, больше для крупного бизнеса
- **Озон Банк** — нет публичного API для счетов, не подходит

## 5. Интеграция с Т-Банк API (реализовано 15.07.2026)

Решение: счёт формирует сама CRM (PDF «счёт-договор оферты» по образцу
`Счёт_Пример.docx`), Invoicing API Т-Банка НЕ используется. Проверка оплаты —
по банковской выписке (OpenAPI `GET /statement`, токен с правом «Выписки»,
env `TBANK_API_TOKEN` + `TBANK_ACCOUNT_NUMBER`).

### Сценарий выставления и оплаты

```
CRM (крон 20-го)                                        Партнёр
 │                                                          │
 ├─ Счёт (BillingInvoice, номер «N-MM») ─────────────────── │
 ├─ Уведомление в колокольчик owner+manager ──────────────► │
 │  (ссылка на PDF /api/billing/invoices/{id}/pdf)          │
 │                                                          │
 │            Т-Банк ◄── платёжка по реквизитам из PDF ──── │
 │               │        (номер счёта в назначении)        │
 ├─ Крон (кажд. 2ч): GET /statement ─► │                    │
 ├─ Матчинг: № счёта → ИНН+сумма → ИНН+Σ                    │
 ├─ applyInvoicePayment: paid, продление подписки,          │
 │  разблокировка, удаление уведомления                     │
```

### Матчинг платежа со счётом (lib/billing/match-bank-operations.ts)
1. Номер счёта «N-MM» в назначении платежа + совпавшая сумма
2. ИНН плательщика + сумма ровно одного незакрытого счёта
3. Несколько счетов с одинаковой суммой на один ИНН (две организации
   Премеленной по 5 000 ₽) — парование только при равенстве числа платежей
   и счетов; одна платёжка на общую сумму закрывает все счета ИНН
4. Иначе — `billing_bank_operations.status=unmatched` (частичная
   оплата/переплата/чужое юрлицо) → ручная разборка в бэк-офисе

### Fallback (если API недоступен)
- Суперадмин вручную отмечает «оплачено» в бэк-офисе (тот же хелпер
  applyInvoicePayment: продление + разблокировка + скрытие уведомления)

## 6. Автоматизация биллинга (реализовано 15.07.2026)

### Кроны (GitHub Actions → /api/cron/*, Bearer CRON_SECRET)
| Крон | Расписание | Что делает |
|------|-----------|------------|
| billing-generate-invoices | `0 6 20-31 * *` | 20-го (и далее ежедневно, идемпотентно) выставляет счета за следующий месяц: сумма по сетке × период, dueDate = 1-е число; уведомление в колокольчик owner+manager со ссылкой на PDF. Организации без ИНН пропускаются (skippedNoInn в ответе) |
| billing-check-payments | `13 5-19/2 * * *` | Сверка выписки Т-Банк (окно 7 дней) с незакрытыми счетами; оплата → продление, разблокировка, скрытие уведомления |
| billing-block-overdue | `30 3 1 * *` | 1-го числа: сперва сверка выписки, затем pending-счета с истёкшим сроком → overdue, организация → blocked (read-only) |

- `Organization.billingExempt` — исключение из автобиллинга (своя/тестовая
  организация): счета не выставляются, автоблокировка не применяется.
  Тумблер в /admin/partners/[id].

### Блокировка = режим «только просмотр» (изменено 15.07.2026)
- billingStatus → "blocked" (крон 1-го числа или вручную суперадмином)
- Страницы, отчёты и любое чтение (GET) РАБОТАЮТ — данные видны
- Мутации к /api/* → 403 `{ code: "BILLING_READ_ONLY" }` (middleware),
  кроме белого списка: /api/billing* (оплата), /api/auth,
  отметка уведомлений прочитанными, телеметрия pageview
- Красная плашка «Счёт не оплачен — CRM в режиме просмотра» на всех
  страницах (billing-banner, живой fetch /api/billing-status, поллинг 60с)
- Ограничение: enforcement по JWT (рефреш ≤5 мин) — блок/разблок
  применяется с задержкой до 5 минут, плашка обновляется сразу
- Данные НЕ удаляются

### Разблокировка
- Автоматически: крон сверки выписки видит оплату → applyInvoicePayment
- Вручную: суперадмин в бэк-офисе — кнопка «Разблокировать» (если деньги
  отправлены, но ещё не поступили) или «Оплачен» на счёте.
  Ручная разблокировка не перезатирается кроном до следующего 1-го числа
  (блокировка срабатывает только на переходе счёта pending → overdue)

## 7. Баланс партнёра в ЛК

### Что видит партнёр на /billing
- Текущий тариф: 5 000 ₽ × N филиалов = X ₽/мес
- Оплаченный период: выбранный (1/3/6/12 мес)
- Оплачено до: DD.MM.YYYY
- Баланс: X ₽ (переплата/долг)
- История операций (таблица):
  - Дата | Операция | Сумма | Статус
  - 01.04 | Счёт №12 | 10 000 ₽ | Оплачен
  - 15.05 | Доплата за филиал | 5 000 ₽ | Ожидает

### Когда возникает баланс
- Переплата (округлил сумму) → положительный баланс → зачтётся
- Доплата за филиал → отрицательный баланс → выставляется счёт
- Возврат → зачисление на баланс (не на карту, прописать в оферте)

## 8. Модель данных (изменения)

### Изменения в BillingSubscription
```
+ billingPeriodMonths  Int       @default(1)    // 1, 3, 6, 12
+ periodEndDate        DateTime                  // дата окончания оплаченного периода
```

### Новая таблица: BillingBalance
```
BillingBalance {
  id              UUID
  organizationId  UUID (FK → Organization)
  type            enum (payment, charge, adjustment, refund)
  amount          Decimal        // + пополнение, − списание
  description     String
  invoiceId       UUID? (FK → BillingInvoice)
  createdAt       DateTime
}
```

### Изменения в BillingInvoice
```
+ periodMonths     Int           // за сколько месяцев счёт
+ branchCount      Int           // филиалов на момент выставления
+ paymentUrl       String?       // ссылка на оплату (от Т-Банк API)
+ paidVia          enum? (bank_transfer, tbank_api, manual)
```
