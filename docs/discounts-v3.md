# Скидки v3 — пер-абонементные шаблоны (опт-ин)

**Статус:** СОГЛАСОВАНО (04.08.2026), реализация не начата. Документ-спека, пишется первым по конвенции «Documentation first».
**Дополняет** (не заменяет) [Скидки v2](discounts-v2.md): добавляет новую ось у шаблонов — *«на абонемент»* — как опт-ин категорию рядом с существующими клиентскими скидками. Движок расчёта (скидка живёт в цене занятия, пропорция по занятиям, деньги при пересчёте) — из v2 без изменений.

## 0. Контекст: отличие от откаченной попытки

04.08.2026 уже строили пер-абонементные скидки (ветка `feature/per-subscription-discounts`, коммит `ca236f5`, merge `e787d48`) и **откатили в тот же день** (revert `56a3593`, миграция отката `20260804160000`). Причина отката: та реализация **заменяла клиентскую модель целиком** — удаляла выбор скидки из карточки клиента (`discount-label.ts`, селект в `edit-client-dialog.tsx`, `client-card-content.tsx`) и переводила весь тип-2 на абонемент принудительно, у всех.

**Эта версия — аддитивная и опт-ин.** Клиентские скидки остаются как в v2. Пер-абонементные включаются явно: тумблер на шаблоне + режим в карточке клиента + гейт в форме абонемента. ~80% «водопровода» из `ca236f5` переиспользуем (см. §9, §11), но НЕ берём: удаление клиентского UI и переименование системного тип-1.

## 1. Модель: ось `scope` у шаблонов

К шаблону скидки добавляется признак **`scope`**:

| `scope` | Смысл | К чему применяется |
|---|---|---|
| **`client`** («Клиентская») | как в v2 | выбирается в карточке родителя, красит скидкой все новые абонементы |
| **`subscription`** («На абонемент») | новое | выбирается по абонементу, красит только тот абонемент, где выбран |

- `scope` есть **только у ручных permanent-шаблонов** (тип-2). Системный тип-1 «Скидка за второй абонемент» (`systemKey='second_subscription'`) — автоматический, без `scope` (у него свой тумблер в настройках). Легаси-шаблоны — без `scope`.
- Существующие permanent-шаблоны при миграции получают `scope='client'` (текущее поведение).
- Название системного тип-1 **не меняется** — остаётся «Скидка за второй абонемент» (в отличие от `ca236f5`).

## 2. Признак шаблона в UI (пункты 1–3 задания)

- **Модалка шаблона** (`settings/discount-templates/page.tsx`): переключатель **«Клиентская» / «Скидка на абонемент»** (задание п.2). Для системного тип-1 и легаси — скрыт/недоступен.
- **Список шаблонов** (`settings/discount-templates`): новая колонка **«Область»** со значением «Клиент» / «Абонемент» (задание п.3). У тип-1 — «Авто» / «—».
- **API** `POST/PUT /api/discount-templates` — принимают `scope` (enum `client|subscription`, дефолт `client`).

## 3. Режим клиента «Шаблоны скидок на абонементы» (пункт 4)

В карточке клиента (`edit-client-dialog.tsx`) селект скидки получает **новый взаимоисключающий пункт** — «Шаблоны скидок на абонементы». Полный набор режимов клиента:

| Режим клиента | Что действует на абонементы |
|---|---|
| **Авто** (Без скидки) — `discountTemplateId=null, perSubDiscountMode=false` | системный тип-1 «за второй абонемент» |
| **Клиентский шаблон X** (`scope=client`) — `discountTemplateId=X` | X на все новые абонементы; тип-1 off |
| **Отключить все** — `autoDiscountDisabled=true` | ничего |
| **Шаблоны скидок на абонементы** (новый) — `perSubDiscountMode=true` | тип-1 **и** клиентский тип-2 **off**; каждый абонемент несёт свой `scope=subscription` шаблон либо ничего |

- Режимы взаимоисключимы. `perSubDiscountMode=true` несовместим с `discountTemplateId != null` и с `autoDiscountDisabled=true` (валидация как у существующего guard #50).
- Хранение: новый флаг `Client.perSubDiscountMode Boolean @default(false)` (в UI — 4-е значение-сентинел селекта, рядом с `templateId | none | NO_AUTO`).

## 4. Пер-абонементный шаблон в форме абонемента (пункт 5)

**Основная развилка задания.** В модалках **создания и редактирования** абонемента (`client-tabs.tsx`, `AddSubscriptionDialog` + `EditSubscriptionDialog`) добавляется меню **«Шаблон скидки на абонемент»**:

- **Активно только когда** у клиента `perSubDiscountMode=true`. Иначе — недоступно (серое) + хинт «Включите режим „Шаблоны скидок на абонементы“ в карточке клиента».
- В списке — **только** активные шаблоны со `scope='subscription'` (+ пункт «Не применять никакую»).
- Выбранный шаблон пишется в `Subscription.discountTemplateId`; скидка применяется через `setSubscriptionManualDiscount` (восстанавливается из `ca236f5`), живёт в `discountPerLesson`, `discountSource='type2'`.
- **Превью стоимости** в форме (`preview-discount.ts` / `GET /api/subscriptions/discount-preview`) получает параметр `discountTemplateId` и считает эффективную цену по выбранному `scope=subscription` шаблону. Держать в синхроне с `recalc-client-discounts.ts` ([[project_discount_preview_mirrors_recalc]]).
- Применимо и к **пакетным** абонементам (у пакета нет месяца периода — тип-1 к нему всё равно неприменим, а ручной пер-абонементный шаблон — да).

## 5. Перенос при выписке (пункт 6)

Массовая (`bulk-renew.ts`) и точечная (`/api/subscriptions/[id]/renew`) выписка на следующий период **переносит `discountTemplateId` исходного абонемента** в новый. Механика — из `ca236f5` (4 согласованные правки: select в `SourceRow`, поле в `BulkRenewCandidate`, `create.data`, вызов `setSubscriptionManualDiscount`).

- Цена занятия нового абонемента — **актуальный прайс направления** (`directionPriceAt`), НЕ цена исходника (защита от двойной скидки, [[project_direction_price_effective_date]]); скидка накладывается заново по перенесённому шаблону.
- Если шаблон к моменту выписки деактивирован — молча не применяется (абонемент без скидки).
- Перенос происходит **независимо** от текущего режима клиента: источник истины — сам абонемент. (Даже если клиент уже вышел из режима «на абонемент», продление абонемента с сохранённым шаблоном несёт скидку дальше — «доживает», см. §7.)

## 6. Взаимодействие тип-1 / тип-2 / пер-абонемент (решение Q1: **режим эксклюзивен**)

Решение владельца 04.08.2026: **режим «на абонемент» эксклюзивен**.

- Когда `perSubDiscountMode=true`, для клиента **не действует** ни системный тип-1 «за второй абонемент», ни клиентский тип-2. Скидку получают **только** абонементы с явно выбранным `scope=subscription` шаблоном; остальные — по полной цене.
- Это ровно та же эксклюзивность, что у клиентского тип-2 в v2 (§1 v2: «тип-2 приоритетен и эксклюзивен, тип-1 не действует вообще»). Технически `perSubDiscountMode` — ещё один признак «у клиента не-авто скидка» в `recalcClientDiscounts`: клиент с этим флагом **исключается из ростера тип-1**.
- Значит coexist-логика `isType1Eligible` из `ca236f5` (тип-1 среди абонементов без ручной скидки) **не нужна** — модель проще.
- На одном абонементе по-прежнему ровно одна скидка.

## 7. Переключение режима клиента (решение Q2: **«доживают»**)

Решение владельца 04.08.2026: существующие абонементы при смене режима **не пересчитываются**.

- Переключение клиента в режим «на абонемент» (или обратно) **НЕ трогает** уже выписанные оплаченные/активные абонементы — их текущие скидки (тип-1, клиентский тип-2) доживают до конца периода. Закон v2 «выданные скидки доживают» (§7 v2).
- Новый режим действует только на **новые** и **выписываемые** (продлеваемые) абонементы.
- Технически: PATCH `/api/clients/[id]` при установке/снятии `perSubDiscountMode` **не запускает** клиентский пересчёт по существующим абонементам (в отличие от смены `discountTemplateId`, которая пересчёт запускает). Это исключает движение денег на живых абонементах (класс правок, давший инцидент Dream 21.07, [[project_discount_current_month_switch]]).
- Симметрично: снятие пер-абонементного шаблона с конкретного абонемента (в форме редактирования) действует на оставшиеся занятия по правилам v2 §3 (пропорция по занятиям), прошлые списания — снимок.

## 8. Движок расчёта — из v2 без изменений

Всё ядро v2 остаётся: скидка = снижение цены занятия (`Subscription.discountPerLesson`, эффективная цена = `max(0, lessonPrice − discountPerLesson)`, cap 0), списания по эффективной цене, прошлые не пересчитываются, пропорция по занятиям, возврат переплаты (`discount_refund` + сторно `transfer_in`), «отхожено» по числу отметок. См. [discounts-v2.md](discounts-v2.md) §3–4. Пер-абонементный шаблон — просто ещё один источник значения `discountPerLesson` на конкретном абонементе.

## 9. Модель данных и миграция

**Схема (новая forward-миграция; откаченную `20260804150000` не оживлять — иначе рушится история Prisma):**

1. Вернуть на `Subscription`:
   - `discountTemplateId String? @map("discount_template_id") @db.Uuid` + relation `discountTemplate DiscountTemplate? @relation("SubscriptionDiscountTemplate", ..., onDelete: SetNull)`; обратная связь `DiscountTemplate.subscriptionsAttached Subscription[]`.
2. Добавить на `DiscountTemplate`:
   - `scope DiscountTemplateScope @default(client)` (enum `client | subscription`) — миграцией существующие permanent → `client`; системный тип-1 и легаси остаются `client` (в UI признак у них скрыт, семантики не несёт).
3. Добавить на `Client`:
   - `perSubDiscountMode Boolean @default(false) @map("per_sub_discount_mode")`.

**Сохраняем без изменений:** `Client.discountTemplateId`, `Client.autoDiscountDisabled`, relation `ClientDiscountTemplate` (клиентская модель жива). `Subscription.discountSource` — переиспользуем значение `type2` для пер-абонементной ручной скидки (различение «клиентский/пер-абонементный» при отчётности — через join к `template.scope`).

1. **Q1 — эксклюзивность режима** (§6): подтверждено владельцем 04.08 — да, тип-1 в режиме «на абонемент» не действует.
