# Браузерное расширение-надстройка над мессенджерами (аналог BubbleXT)

> Статус: **план / R&D**. Обновлено 28.08.2026.
> Это рабочая спека проекта расширения — единая точка правды при разработке
> (в т.ч. со второй машины/ноутбука). Код расширения в этом репозитории пока
> отсутствует; сделан только первый шаг на стороне CRM — поля-хендлы в карточке.

## 1. Зачем и что это

Конкурент **AlfaCRM** имеет надстройку **BubbleXT** (bubblext.ru) — браузерное
расширение (Chrome / Яндекс / Edge), которое встраивает карточку клиента прямо
рядом с чатом в веб-мессенджерах и даёт админу действовать не выходя из чата.
Слоган: «Хватит переключаться между CRM и чатом». Мы делаем **свой аналог для
CRMka** — это сильный дифференциатор в нише детских центров, где вся переписка с
родителями живёт в WhatsApp/Telegram.

**Что делает BubbleXT (наш референс по фичам):**
- боковая панель у чата с карточкой клиента: баланс, абонементы, группы, расписание;
- из чата: создать оплату, задачу, комментарий; сгенерировать ссылку на онлайн-оплату;
- ИИ-ассистент предлагает черновик ответа по данным центра;
- обратная сторона: в карточку CRM встраивает кнопки перехода в чат и последние сообщения;
- работает «локально» (ключ доступа к AlfaCRM не уходит на их сервер), т.к. они
  — третья сторона к чужой CRM.
- Цена BubbleXT: от 825 ₽/мес за 4 мессенджера, 3 рабочих места, 30 дней бесплатно.

**Наше преимущество:** мы владеем CRMka → делаем нормальную первопартийную
авторизацию по токену и серверный агрегатор-эндпоинт, без «локального» костыля
с пользовательским API-ключом.

## 2. Стратегия: WhatsApp-first

Ключевой факт: премиса «сопоставляем клиента по телефону» честно работает
**только в WhatsApp** (там id чата = номер, `<phone>@c.us`). В Telegram и ВК
телефон недоступен (приватность) → матч по **username/id**. MAX — привязан к
номеру, но веб-DOM новый и, вероятно, номер прячет.

Поэтому:
1. **MVP = только WhatsApp.** Там и главная боль, и матч по телефону работает.
2. Telegram/ВК добавляем позже — по хендлам (см. §4, поля уже заведены).
3. MAX — отдельный R&D-спайк неизвестного размера (DOM недокументирован).

## 3. Архитектура расширения (MV3)

- **Content script** на host'ах мессенджеров монтирует корень с **Shadow DOM**
  (изоляция CSS панели от стилей мессенджера) → рендерит панель-карточку.
- **MAIN-world скрипт** (`content_scripts[].world: "MAIN"`, Chrome 111+) читает
  внутреннее состояние SPA мессенджера (для WhatsApp — Store через
  moduleRaid/wa-js) → достаёт идентификатор активного чата (JID/телефон),
  отдаёт его в isolated content script через `window.postMessage`.
- **Service worker** делает кросс-доменные запросы к API CRMka (у него есть
  `host_permissions` → обходит CORS контент-скрипта). Держит токен в
  `chrome.storage`.
- Смену чата ловим `MutationObserver` + поллинг активного id (SPA без навигации).
- Единый UI + сменные **адаптеры на мессенджер** (селекторы + стратегия
  идентичности). moduleRaid/wa-js **бандлятся внутрь** (MV3 запрещает remote code).

## 4. Данные в CRMka: поля-хендлы (СДЕЛАНО 28.08.2026)

Добавлены в модель `Client` (миграция `20260828120000_client_messenger_handles`):
- `telegram` — @username / ссылка / id;
- `vk` — vk.com/id... / screen_name;
- `max` — телефон / ссылка.

Свободный текст, nullable, отдельно от общего `socialLink`. Проведены через:
`prisma/schema.prisma`, `api/clients/route.ts` (создание), `api/clients/[id]/route.ts`
(правка), `api/clients/merge/route.ts` (перенос при слиянии дублей), формы
create/edit клиента, блок «Информация» карточки, справку PageHelp.
Матч по телефону (WhatsApp) использует существующий `findClientsByPhone`
(`lib/clients/find-by-phone.ts`); для Telegram/ВК матч пойдёт по этим полям
(позже — индексы отдельной миграцией).

## 5. Что на бэкенде CRMka уже есть (переиспользуем)

| Нужно расширению | Есть в коде |
|---|---|
| Клиент по телефону | `findClientsByPhone` + `phoneMatchKey`/`normalizePhone` (`lib/clients/find-by-phone.ts`, `lib/phone.ts`); `GET /api/clients/search?withPhone=1` |
| Карточка: баланс/абонементы/расписание | `GET /api/clients/[id]`, `GET /api/subscriptions?clientId=`, `GET /api/clients/[id]/schedule`, `.../timeline`, `.../communications` |
| Оплата / задача / комментарий | `POST /api/payments`, `POST /api/tasks`, `POST /api/clients/[id]/communications` (+`logClientNote`) |
| ИИ-релей | `POST /api/ai/chat` (провайдер-свитч, релей на Hetzner, логи, лимиты) |
| Мессенджер→клиент по номеру (прецедент) | вебхук `api/webhooks/wazzup/route.ts` уже резолвит клиента по телефону и пишет Communication |
| Пример отдельной auth-поверхности | ЛК родителя (`lib/portal-auth.ts`, jose-JWT) |

## 6. Что на бэкенде НЕ хватает (построить)

1. **Авторизация внешнего клиента.** Сейчас `next-auth` JWT в **httpOnly-cookie**,
   привязанной к домену CRMka (`SameSite=lax`) — расширение с `web.whatsapp.com`
   её не пошлёт, а токенов доступа (PAT) для сотрудников **нет**. Нужно:
   выпуск персонального токена сотрудника в «Настройках» + приём
   `Authorization: Bearer` в middleware и роутах (сейчас все ждут cookie-сессию).
   Токен ограничить скоупом (какие эндпоинты) и атрибутировать действия сотруднику.
2. **CORS.** В `next.config.ts` только редиректы, `Access-Control-Allow-*` нет,
   `OPTIONS`-preflight нет. Нужен строгий allow-list origin'ов мессенджеров.
3. **Агрегатор-эндпоинт** `GET /api/ext/client-card` — баланс+абонементы+
   расписание+последние сообщения одним компактным ответом (сейчас 3-4 запроса).
4. **ИИ-режим «черновик ответа».** Текущий `/api/ai/chat` — навигационный
   Q&A-бот с фиксированным промптом, без контекста переписки. Нужен новый
   промпт/эндпоинт (обвязка релея переиспользуется).
5. **Чтение ветки переписки** (для контекста/ИИ). Wazzup только пишет входящие,
   наружу их не отдаёт; Telegram-входящих нет.
6. Рейт-лимиты/анти-абуз на новые публичные (CORS) эндпоинты.

## 7. Оценка и риски

- **Бэкенд-доработки** (PAT + CORS + агрегатор + ИИ-черновик): ~1–2 недели.
- **MVP WhatsApp** (панель, MAIN-world мост, извлечение номера, детект чата,
  lookup, «не найдено/новый лид»): ~1–1.5 мес опытного extension-разработчика.
- **Полный 4-мессенджера** (не линейно): ~3–5 мес + **постоянно ~0.2–0.5 FTE**
  на поддержку хрупких DOM-адаптеров.

**Риски:**
- матч по телефону — только WhatsApp; Telegram/ВК — по хендлам; MAX не проверен;
- WhatsApp LID (`<id>@lid`) прячет номер у части чатов даже во внутреннем Store;
- MAX — новый, DOM нестабилен/обфусцирован, библиотек нет;
- сопровождение: 4 независимые поверхности поломки, классы плавают;
- Store/ToS: Meta выпиливает WhatsApp-расширения (окт.2025 — 100+); скрейпинг
  веб-клиентов нарушает ToS; с 01.08.2026 CWS ужесточил раскрытие данных;
- **152-ФЗ**: вытягивание идентичности клиента из мессенджера — обработка ПДн;
- дистрибуция: один MV3-билд под Chrome/Edge/Яндекс; для B2B удобнее **Unlisted**
  в CWS + enterprise-CRX для быстрых хотфиксов.
